# SimpleRay изнутри — как устроена программа

Обучающий разбор проекта **для новичка**. Цель — чтобы, прочитав этот документ,
человек без опыта понял, из чего собрана программа, зачем каждый кусок нужен и как
всё работает вместе. Технические слова объясняются по ходу; в конце есть словарик.

> Рядом лежит иллюстрированная версия — `SimpleRay-Guide.pdf` (те же идеи, но со схемами).

---

## 0. Что это за программа и какую задачу решает

**SimpleRay** — это клиент VPN для Windows. «Клиент» значит: программа, которую
ставит себе пользователь; она соединяется с вашим сервером в интернете и пускает
через него трафик. Зачем: обойти блокировки, спрятать трафик, выбрать, какой стране
показать ваш «выходной» адрес.

Внутри программа не изобретает шифрование сама — она **управляет** проверенным
движком `sing-box` (отдельная программа-«ядро»). SimpleRay — это удобная оболочка:
красивое окно, хранение профилей, настройки маршрутизации, кнопка «Подключить».

Аналогия: `sing-box` — это мотор, а SimpleRay — это машина вокруг мотора (руль,
панель, кресла). Мотор мощный, но пользоваться голым мотором неудобно.

---

## 1. Общая картина: из каких частей собрана программа

Проект разделён на **два подпроекта** (в мире .NET это называется «сборки»/проекты):

| Проект | Что внутри | Особенность |
|--------|-----------|-------------|
| **SimpleRay.Core** | «Мозги»: разбор ссылок, генерация конфигурации, правила — чистая логика | Не знает про Windows и окна. Можно переиспользовать (например, под Android). |
| **SimpleRay.App** | «Лицо»: окно, кнопки, запуск процессов, файлы | Только Windows (WPF). |

Ещё есть **тесты** (`SimpleRay.Core.Tests`, `SimpleRay.App.Tests`) — программы,
которые автоматически проверяют, что код работает правильно.

**Почему делят на Core и App?** Чтобы «мозги» не были связаны с конкретной
операционной системой. Логику разбора ссылок можно проверить тестами без окна, и
завтра переиспользовать в мобильной версии. Это называется **разделение
ответственности**: каждый кусок отвечает за одно.

Технологии: язык **C#**, платформа **.NET 8**, интерфейс на **WPF** (стандартная
технология окон для Windows).

## 2. Главная идея безопасности: TUN, а не «дырка на localhost»

Самое важное архитектурное решение. Многие VPN-клиенты поднимают у себя локальный
**прокси** — открывают порт на `127.0.0.1` (адрес «сам себя»), и приложения ходят
через него. Проблема: этот порт часто **без пароля**, и любая программа на
компьютере (даже вредоносная) может им пользоваться как бесплатным туннелем.

SimpleRay идёт другим путём — **TUN-режим**. sing-box создаёт виртуальную сетевую
карту (через `wintun`), и **весь** сетевой трафик системы автоматически идёт через
неё. Локального прокси-порта **вообще нет** → и «дырки» нет. Уязвимость закрыта
не заплаткой, а самой конструкцией.

Это настолько важно, что в проекте есть тест `AntiLeakTests`, который проверяет:
в сгенерированной конфигурации **никогда** нет входящего прокси (socks/http/mixed).
Если кто-то случайно его добавит — тест упадёт.

## 3. Как устроено окно: WPF и паттерн MVVM

Окно сделано по паттерну **MVVM** (Model — View — ViewModel). Это способ разложить
интерфейс на три слоя, чтобы логика не перемешивалась с кнопками:

- **View** (вид) — это `MainWindow.xaml`: разметка окна на языке XAML (похоже на
  HTML). Кнопки, списки, надписи. View **ничего не считает** — только показывает.
- **ViewModel** (модель представления) — `MainViewModel.cs`: тут вся логика окна.
  Какие профили в списке, что делает кнопка «Подключить», текст статуса.
- **Model** (модель) — данные: `ProfileConfig`, `RoutingSettings` из Core.

Связь между View и ViewModel — это **привязки** (binding). В XAML пишем
`Content="{Binding ConnectButtonText}"` — и надпись на кнопке автоматически берётся
из свойства `ConnectButtonText` во ViewModel. Изменилось свойство → надпись
обновилась сама. Программисту не нужно вручную «перерисовывать».

Чтобы привязки узнавали об изменениях, ViewModel умеет «кричать» — механизм
`INotifyPropertyChanged` (в проекте — базовый класс `ObservableObject`). Свойство
поменялось → шлётся уведомление → интерфейс перечитывает значение.

**Команды** (`RelayCommand`) — это «кнопка как объект»: у команды есть метод
`Execute` (что делать по нажатию) и `CanExecute` (можно ли сейчас нажимать). Кнопка
в XAML привязана к команде — и сама становится серой, когда нажимать нельзя.

## 4. Путь профиля: от строчки-ссылки до живого туннеля

Это «конвейер» — главный сценарий программы. Разберём по шагам.

1. **Пользователь добавляет профиль.** Обычно это ссылка вида
   `vless://…@server:443?...#Имя`. Её кладут из буфера, файла, QR-кода или подписки.
2. **Разбор ссылки** — `ShareLinkParser` (в Core). Он превращает строку в понятный
   объект `ProfileConfig` (сервер, порт, ключи, шифрование, транспорт). Для каждого
   протокола (VLESS, VMess, Trojan, Shadowsocks, WireGuard) — свой разборщик.
3. **Хранение** — профиль сохраняется в файл `profiles.json` (см. раздел 6).
4. **Нажатие «Подключить»** — `MainViewModel.ToggleConnectionAsync`. Программа:
   - собирает список серверов (один или группа);
   - генерирует **конфигурацию для sing-box** — `SingBoxConfigGenerator` (в Core)
     превращает `ProfileConfig` + настройки маршрутизации в большой JSON-текст,
     который понимает sing-box;
   - запускает движок.
5. **Движок** — `SingBoxEngine` запускает `sing-box.exe` как дочерний процесс,
   отдав ему конфиг. sing-box поднимает TUN, и туннель заработал.

Ключевая мысль: Core только **описывает намерение** (какой сервер, какие правила) в
виде JSON. Реальную работу с сетью делает sing-box. Мы даже проверяем правильность
JSON командой `sing-box check` до запуска — как проверка орфографии перед печатью.

## 5. Движок: как управлять чужой программой

`SingBoxEngine` — «дирижёр» дочернего процесса. Интересные моменты:

- **`IVpnEngine`** — это **интерфейс** (контракт): «движок умеет Start/Stop, у него
  есть состояние и события лога». Конкретная реализация под Windows —
  `SingBoxEngine` (запускает процесс). Завтра под Android будет другая реализация
  того же контракта. ViewModel зависит от контракта, а не от конкретики — это делает
  код гибким.
- **Состояния** (`EngineState`): Stopped → Starting → Running → Stopping, плюс
  Faulted (сбой). Окно подписано на смену состояния и меняет надписи/цвета.
- **Аккуратная остановка.** Просто «убить» процесс плохо — sing-box не успеет убрать
  за собой сетевые маршруты, и можно остаться без интернета. Поэтому сначала
  посылаем сигнал «заверши работу культурно» (Ctrl+C через `ConsoleCtrlTerminator`),
  и только если не помогло — убиваем принудительно. Это защита «от глюков».

## 6. Хранение данных и безопасность на диске

Профили и настройки лежат в папке пользователя `%AppData%\SimpleRay`. Тут несколько
приёмов «чтобы не было проблем»:

- **Шифрование секретов.** `profiles.json` содержит пароли/ключи. Их нельзя хранить
  открытым текстом. Используется **DPAPI** (`EncryptedFile`) — встроенное шифрование
  Windows, привязанное к учётной записи: файл сможет прочитать только этот
  пользователь на этом компьютере.
- **Атомарная запись** (`AtomicFile`). Пишем не прямо в файл, а во временный, потом
  «подменяем» одним движением. Если в момент записи выключат свет — старый файл
  цел, не будет «половинки».
- **Версия схемы** (`schemaVersion`). В файле хранится номер формата. Если завтра
  формат поменяется, новая версия поймёт старый файл и переедет на новый — данные не
  потеряются. Плюс поддержка совсем старых файлов без версии.

## 7. Маршрутизация: куда пойдёт каждый пакет

VPN не обязан гнать через сервер **весь** трафик. SimpleRay умеет «раскидывать»:

- **Режимы:** «Глобально» (всё через VPN), «По правилам» (разделять), «Напрямую».
- **geoip / geosite** — базы «какой адрес/сайт к какой стране относится». Например,
  российские сайты можно пускать напрямую, а остальное — через VPN.
- **По приложениям** — конкретные программы (по имени процесса) можно принудительно
  пускать через VPN или мимо.
- **Группа каналов (failover)** — несколько серверов объединяются, и sing-box сам
  переключается на живой/быстрый (правило `urltest`). Упал один — трафик пошёл через
  другой.
- **Блокировка рекламы** — правило `reject` для рекламных доменов.

Всё это — просто **правила в JSON**, которые генерирует `SingBoxConfigGenerator`.
Порядок правил важен: sing-box берёт **первое подходящее**, поэтому правила «по
приложениям» стоят раньше правил «по гео» (тест `AntiLeakTests` это проверяет).

## 8. Локализация: смена языка «на лету»

Интерфейс переведён на 9 языков и переключается **без перезапуска**. Как это
работает (упрощённо):

- Все надписи хранятся не в коде, а в файлах `Localization/langs/*.json` — по одному
  на язык, где `ключ → перевод`.
- `LocalizationManager` — «переводчик»: по ключу отдаёт строку текущего языка.
- В XAML пишем `{loc:Loc connect.connect}` вместо готового текста. Это привязка к
  переводчику по ключу.
- Меняем язык → переводчик «кричит» об изменении → **все** привязки перечитывают
  свои строки → окно мгновенно на новом языке. Для арабского/фарси ещё
  переключается направление письма (справа налево).

Красивый бонус: тест `LocalizationTests` проверяет, что во **всех** языках
одинаковый набор ключей и не потеряны подстановки вроде `{0}`. Забыл перевести одну
строку — тест упадёт.

## 9. Обновления и откат

Программа умеет обновлять себя сама, но **безопасно**:

1. **Проверка.** Спрашивает у GitHub «какой последний релиз», сравнивает номер
   версии со своей.
2. **Согласие.** Ничего не качает без «да» пользователя.
3. **Загрузка + проверка.** Качает архив и сверяет его **контрольную сумму SHA256**
   — гарантия, что файл не побился/не подменён при передаче.
4. **Применение.** Нельзя переписать программу «на ходу» (она запущена). Поэтому
   делается копия обновлятора во временную папку; она ждёт, пока программа закроется,
   подменяет файлы и запускает новую версию.
5. **Откат.** Перед подменой делается резервная копия. Новая версия запускается и
   «наблюдается» несколько секунд: если она сразу падает — обновлятор
   **восстанавливает старую** версию. «Не завёлся мотор — вернули прежний».

Важная деталь про доверие: контрольная сумма берётся с того же GitHub, поэтому она
защищает от порчи при передаче, но корень доверия — это ваш GitHub-аккаунт. Чтобы
подпись была «настоящей», нужен сертификат подписи кода (пока его нет — Windows
показывает «неизвестный издатель»).

## 10. Сборка, тесты и выпуск (CI/CD)

- **Portable** — самодостаточная папка: `SimpleRay.exe` (с рантаймом .NET внутри) +
  `core/` + `geo/`. Ничего ставить не надо, просто запустить.
- **Установщик** — Inno Setup (`scripts/installer.iss`) кладёт то же самое с ярлыками
  и деинсталляцией.
- **Тесты** — 95+ автоматических проверок. Запуск: `dotnet test`.
- **CI/CD** — GitHub Actions:
  - `ci.yml` — на каждое изменение собирает и прогоняет тесты (страховка от поломок).
  - `release.yml` — как только ставишь тег версии (`v0.2.0`), сам собирает пакет,
    установщик и публикует релиз. Выпуск = один `git tag` + `git push`.

## 11. Как читать этот проект новичку

**С чего начать в коде** (по нарастанию сложности):

1. `SimpleRay.Core/Models/ProfileConfig.cs` — простой объект-«коробка» с данными.
   Понять, какие поля у профиля.
2. `SimpleRay.Core/Profiles/ShareLinkParser.cs` — как строка превращается в объект.
3. `SimpleRay.Core/Config/SingBoxConfigGenerator.cs` — как объект превращается в JSON.
4. `SimpleRay.App/ViewModels/MainViewModel.cs` — логика окна (тут «клей»).
5. `SimpleRay.App/MainWindow.xaml` — разметка окна.
6. Тесты в `tests/` — лучший способ понять, что и как должно работать: каждый тест
   это маленький пример «дано → ожидаем».

**Как собрать и запустить** (нужен .NET 8 SDK):
```bash
dotnet build              # собрать
dotnet test               # прогнать тесты
dotnet run --project src/SimpleRay.App   # запустить окно
```
Для настоящего подключения нужны права администратора (TUN) и рабочий сервер.

## Словарик терминов

- **VPN-клиент** — программа, соединяющая ваш компьютер с VPN-сервером.
- **sing-box** — движок (отдельная программа), делающий саму сетевую работу.
- **TUN** — виртуальная сетевая карта; через неё уходит весь трафик системы.
- **wintun** — драйвер, дающий такую карту на Windows.
- **Прокси на localhost** — локальный порт-туннель; у нас его сознательно НЕТ.
- **Профиль (ProfileConfig)** — описание одного сервера (адрес, ключи, протокол).
- **Протоколы (VLESS/VMess/Trojan/Shadowsocks/WireGuard)** — способы «завернуть» и
  зашифровать трафик до сервера.
- **JSON** — текстовый формат данных; на нём пишется конфиг для sing-box.
- **WPF** — технология окон Windows.
- **XAML** — язык разметки окон (похож на HTML).
- **MVVM** — раскладка интерфейса на View / ViewModel / Model.
- **Binding (привязка)** — автоматическая связь «данные ↔ элемент окна».
- **Интерфейс (в C#)** — контракт «что умеет объект», без реализации.
- **Async / await** — способ делать долгие операции (сеть, файлы), не «замораживая»
  окно.
- **DPAPI** — встроенное в Windows шифрование данных под учётную запись.
- **geoip / geosite** — базы соответствия адресов/сайтов странам.
- **failover** — автопереключение на запасной канал при сбое.
- **CI/CD** — автоматическая сборка/тесты/выпуск на сервере (GitHub Actions).
- **SHA256** — «отпечаток» файла для проверки целостности.
- **Тест (unit-тест)** — маленькая программа, проверяющая кусок кода.
