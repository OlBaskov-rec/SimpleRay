# Аудит перед переводом репозитория в public

**Дата:** 2026-07-25
**Область:** весь git-репозиторий SimpleRay — рабочее дерево и **вся история**
(31 коммит по всем веткам/тегам).
**Цель:** убедиться, что при открытии репозитория (public) не утекут секреты,
ключи или личные данные. Public-репозиторий нужен, чтобы заработала встроенная
автообновлялка (без авторизации GitHub API отдаёт 404 на приватный репозиторий).

## Итог

**Критичных находок нет. Репозиторий можно открывать** после того, как вы
примете решение по двум заметкам ниже (обе — не про утечку из кода).

Переписывать историю git **не требуется**.

## Заметки (решение за вами — не блокеры)

1. **Тестовый WireGuard-ключ в юнит-тестах.**
   В `tests/SimpleRay.Core.Tests/WireGuardTests.cs` и `ConfigEmitTests.cs` есть
   пара ключей (`PrivateKey = SC7/JBU2…=`). Это одноразовый ключ **без реального
   сервера/пира** — сам по себе он ничего не открывает (32 случайных байта).
   Утечкой не является. *По желанию* можно заменить на явно-«игрушечный», но
   переписывать историю ради этого не нужно.

2. **E-mail автора виден в метаданных коммитов.**
   Все коммиты подписаны `inbasko@gmail.com`. После открытия репозитория этот
   адрес станет виден в истории (сейчас он и так есть в вашем аккаунте). Варианты:
   - принять как есть;
   - для будущих коммитов использовать GitHub noreply
     (`OlBaskov-rec@users.noreply.github.com`);
   - при желании — переписать историю (не обязательно).

## Защита на будущее

`.gitignore` дополнен оборонительными правилами (на случай, если реальный файл
данных случайно скопируют в репозиторий во время отладки):
`**/profiles.json`, `**/subscriptions.json`, `/settings.json`, `last-error.txt`,
`lang.txt`, `*.conf` (импортируемые WireGuard-конфиги), `*.p12`, `*.pvk`
(`*.pfx` и `.env` уже игнорировались).

Реальные данные пользователя (`profiles.json`, `settings.json`,
`subscriptions.json`, `lang.txt`, `last-error.txt`) программа хранит в
`%AppData%\SimpleRay`, **вне репозитория** — штатной работой они в git не попадут.
