# Проверка kill-switch (WFP) на реальной машине

Пошаговый прогон, чтобы убедиться, что kill-switch **блокирует утечки** и **корректно
восстанавливается** после сбоя. Технический дизайн — в [KILL-SWITCH.md](KILL-SWITCH.md).

> ⚠️ **Важно.** Kill-switch — fail-closed: он может **заблокировать весь интернет** на этой
> машине (это и есть его работа). Прежде чем начинать, прочитайте раздел
> «Как восстановить сеть» ниже и держите под рукой **второе устройство** (телефон), чтобы
> заглянуть в инструкцию, если основной ПК останется без сети.

---

## 0. Что понадобится

- Windows 10 (1809+) или 11, x64.
- **Права администратора** (WFP-фильтры ставятся только elevated; приложение само запросит
  UAC при подключении).
- **Рабочий VPN-профиль**, который точно подключается без kill-switch.
- Свежая сборка из текущего кода (см. ниже).
- Желательно: второе устройство с интернетом на случай блокировки.

---

## Как восстановить сеть, если её заблокировало

Любой из способов вернёт доступ (от быстрого к гарантированному):

1. **В приложении** нажмите «Отключить» — фильтры снимаются сразу.
2. Если приложение зависло/закрылось: **запустите SimpleRay снова от имени
   администратора** — при старте `CleanupLeftovers` удаляет оставшиеся фильтры.
   (ПКМ по `SimpleRay.exe` → «Запуск от имени администратора». Обычный запуск с
   последующим «Подключить» тоже поднимет UAC и очистит.)
3. **Перезагрузка** — гарантированно чистит фильтры (они не boot-persistent).

Ручного удаления через `netsh` нет — фильтры снимаются только приложением или перезагрузкой.


## 2. Шпаргалка диагностических команд

Открыть **PowerShell от администратора** и держать рядом:

```powershell
# Показать все WFP-фильтры и найти наши (создаёт filters.xml в текущей папке)
netsh wfp show filters
Select-String -Path .\filters.xml -Pattern "SimpleRay kill-switch"

# Найти TUN-адаптер приложения (должен называться simpleray / драйвер wintun)
Get-NetAdapter | Where-Object { $_.Name -like '*simpleray*' -or $_.InterfaceDescription -like '*wintun*' } |
  Format-Table Name, InterfaceDescription, ifIndex, Status

# Быстрая проверка доступа (при блокировке — таймаут/ошибка)
curl.exe -m 5 https://example.com    ; "exit=$LASTEXITCODE"
# Проверка IPv6 отдельно
curl.exe -6 -m 5 https://ipv6.google.com ; "exit=$LASTEXITCODE"

# Убить процессы для сценариев сбоя
Stop-Process -Name sing-box -Force     # имитация краха движка
Stop-Process -Name SimpleRay -Force    # имитация краха приложения
```

Для наглядной проверки утечки IPv6 удобно открыть в браузере **https://test-ipv6.com**
или **https://ipleak.net** (при поднятом туннеле и включённом kill-switch адрес должен быть
серверный, а при разрыве — доступа быть не должно, а не «ваш реальный IP»).

Если `Engage` не сработал, приложение покажет статус «Подключено, но kill-switch включить не
удалось: …», а подробности — в поле лога и в `%AppData%\SimpleRay\last-error.txt`.

## 3. Тесты по шагам

Отмечайте результат в таблице в конце. «Ожидание» — что должно быть; «Если не так» —
на что это указывает.

### Тест 1. База без kill-switch
- **Действие:** галочка kill-switch **выключена**. Подключиться. Открыть сайт, `curl.exe -m 5 https://example.com`.
- **Ожидание:** интернет работает как обычно.
- **Если не так:** проблема не в kill-switch, а в самом профиле/туннеле — сначала почините базовое подключение.

### Тест 2. Обычный сёрфинг с включённым kill-switch
- **Действие:** отключиться. Включить галочку **kill-switch**. Подключиться (UAC). Открыть сайт, `curl.exe -m 5 https://example.com`.
- **Ожидание:** интернет по-прежнему работает (разрешены TUN + sing-box + loopback).
- **Если не так (интернета нет при живом туннеле):** неверен permit-фильтр — вероятнее всего **LUID TUN-интерфейса** (Тест-помощник ниже) или **app-id sing-box**. Это главный признак ошибки в нативном слое. Снимите блок («Отключить») и пришлите вывод из раздела 4.
- **Проверка фильтров:** `netsh wfp show filters` → в `filters.xml` должны быть записи «SimpleRay kill-switch» (block-all + permit-*).

### Тест 3. Крах движка (главный сценарий)
- **Действие:** при подключении с kill-switch убить sing-box: `Stop-Process -Name sing-box -Force`. Сразу же `curl.exe -m 5 https://example.com` несколько раз в течение ~5–15 сек.
- **Ожидание:** в момент разрыва запросы **не проходят** (блокировка, нет утечки); затем watchdog переподключается («переподключение (n/5)…»), и доступ восстанавливается через туннель.
- **Если не так (сайт открывается напрямую сразу после убийства sing-box):** это **утечка** — block-фильтр не работает или снялся раньше времени. Зафиксируйте и пришлите вывод.

### Тест 4. IPv6 при разорванном туннеле
- **Действие:** при подключении с kill-switch убить sing-box и быстро `curl.exe -6 -m 5 https://ipv6.google.com` (или открыть test-ipv6.com).
- **Ожидание:** IPv6-доступа **нет** в момент разрыва (нет утечки по IPv6).
- **Если не так:** отсутствует/неверен block-фильтр на слое **ALE_AUTH_CONNECT_V6**.

### Тест 5. Крах приложения — fail-closed + восстановление
- **Действие:** при подключении с kill-switch убить **само приложение**: `Stop-Process -Name SimpleRay -Force`. Проверить доступ (`curl.exe -m 5 https://example.com`).
- **Ожидание:** трафик **заблокирован** (fail-closed — фильтры пережили краш приложения). Затем запустить SimpleRay **от администратора** → фильтры снимаются (`CleanupLeftovers`), доступ восстановлен. Отдельно проверить, что **перезагрузка** тоже возвращает доступ.
- **Если не так (после краха приложения интернет есть):** сессия оказалась динамической, а не fail-closed — пришлите вывод.

### Тест 6. Чистое отключение не оставляет следов
- **Действие:** подключиться с kill-switch, затем «Отключить». `netsh wfp show filters` → искать «SimpleRay».
- **Ожидание:** фильтров «SimpleRay kill-switch» **не осталось**.
- **Если не так:** утечка фильтров (Disengage не всё удаляет).

### Тест 7. Отказ WFP не ломает подключение
- **Действие:** (опционально) запустить приложение **без** прав администратора и попробовать подключиться с kill-switch — WFP открыть не удастся.
- **Ожидание:** статус «Подключено, но kill-switch включить не удалось: …», при этом соединение живёт (fail-safe), а не рвётся и не блокирует наполовину.

### Тест-помощник: проверить имя TUN-интерфейса
Если Тест 2 показал «нет интернета», чаще всего дело в том, что permit-фильтр разрешает не
тот интерфейс. Приложение вычисляет LUID по alias через `ConvertInterfaceAliasToLuid("simpleray")`,
поэтому адаптер должен называться именно **simpleray**:
```powershell
Get-NetAdapter | ? { $_.Name -like '*simpleray*' -or $_.InterfaceDescription -like '*wintun*' } |
  Select-Object Name, ifIndex, InterfaceDescription, Status
```
Если в колонке `Name` не «simpleray» (значение совпадает с `GeneratorOptions.TunInterfaceName`),
permit-фильтр интерфейса не сработает — сообщите фактическое имя.

## 4. Что прислать при провале любого теста

Чтобы я поправил нативный слой, пришлите:

1. Номер и название теста, что именно пошло не так.
2. Вывод:
   ```powershell
   netsh wfp show filters
   ```
   и найденные строки: `Select-String .\filters.xml -Pattern "SimpleRay" -Context 0,20`
3. `Get-NetAdapter | ? { $_.Name -like '*simpleray*' -or $_.InterfaceDescription -like '*wintun*' } | fl *`
4. Содержимое `%AppData%\SimpleRay\last-error.txt` (если есть) и текст статуса/лога из приложения.
5. Версия Windows: `winver` или `[System.Environment]::OSVersion`.

По этим данным видно, какой из фильтров (block-all / permit-tun / permit-singbox /
IPv6-слой) ведёт себя не так.
